# TaskTrack

TaskTrack is a small task manager built with **Spring Boot** and **plain HTML/CSS/JavaScript**. You can create, view, edit, complete and delete tasks. Data is stored in a file-based H2 database so tasks survive restarts.

## Why TaskTrack exists

TaskTrack is the practice project for **Hack the Web**, an open-source contribution competition. The core app works, and a set of beginner-friendly improvements is waiting to be built. You clone the repository, run it locally, pick an issue, implement it, and open a pull request for points.

## Features

- Create, edit, delete tasks, and mark them complete or pending
- Title, description, priority (Low/Medium/High), due date
- Summary counts (total, pending, completed)
- Filter by All / Pending / Completed
- Loading state, empty state, success and error messages
- Delete confirmation, responsive layout, keyboard and screen-reader friendly
- REST API with validation and JSON error responses

## Technology stack

| Layer | Technology |
|---|---|
| Frontend | HTML, CSS, vanilla JavaScript (Fetch API). No frameworks or build tools |
| Backend | Java 21, Spring Boot 3.3.x, Spring Web, Spring Data JPA, Bean Validation |
| Database | H2 (file-based) |
| Build | Maven |

## Prerequisites

- **Java 21** (`java -version` should show 21)
- **Maven 3.9+** (`mvn -version`)
- Internet access the first time, so Maven can download dependencies
- A modern web browser

## Run it

**macOS / Linux**

```bash
git clone <your-fork-url>
cd tasktrack
mvn spring-boot:run
```

**Windows (PowerShell or Command Prompt)**

```powershell
git clone <your-fork-url>
cd tasktrack
mvn spring-boot:run
```

Then open **http://localhost:8080** in your browser. Stop the app with `Ctrl+C`.

To build a runnable jar instead: `mvn clean package` then `java -jar target/tasktrack-1.0.0.jar`.

## API

Base path: `/api/tasks`. The frontend and API share one origin, so no CORS setup is needed.

| Method | Endpoint | Description | Success |
|---|---|---|---|
| GET | `/api/tasks` | List all tasks (newest first) | 200 |
| GET | `/api/tasks/{id}` | Get one task | 200 |
| POST | `/api/tasks` | Create a task | 201 |
| PUT | `/api/tasks/{id}` | Update a task | 200 |
| DELETE | `/api/tasks/{id}` | Delete a task | 204 |

### Task JSON

```json
{
  "id": 1,
  "title": "Complete DSA practice",
  "description": "Solve two graph problems",
  "status": "PENDING",
  "priority": "HIGH",
  "dueDate": "2026-10-30",
  "createdAt": "2026-10-24T10:15:30.123"
}
```

| Field | Rules |
|---|---|
| `id` | Generated by the server. Ignored if sent |
| `title` | Required, not blank, max 100 characters |
| `description` | Optional, max 500 characters |
| `status` | `PENDING` or `COMPLETED` |
| `priority` | `LOW`, `MEDIUM` or `HIGH` |
| `dueDate` | Optional, format `yyyy-MM-dd` |
| `createdAt` | Generated by the server on creation. Never changes. Ignored if sent |

### Create

When `status` is omitted it defaults to `PENDING`, and `priority` defaults to `MEDIUM`.

```bash
curl -X POST http://localhost:8080/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"Complete DSA practice","description":"Solve two graph problems","priority":"HIGH","dueDate":"2026-10-30","status":"PENDING"}'
```

### Update

`PUT` replaces all editable fields. **`title`, `status` and `priority` are required.** `description` and `dueDate` are optional; sending `null` or omitting them clears them. `id` and `createdAt` never change.

```bash
curl -X PUT http://localhost:8080/api/tasks/1 \
  -H "Content-Type: application/json" \
  -d '{"title":"Complete DSA practice","status":"COMPLETED","priority":"HIGH","dueDate":"2026-10-30"}'
```

### Other requests

```bash
curl http://localhost:8080/api/tasks
curl http://localhost:8080/api/tasks/1
curl -X DELETE http://localhost:8080/api/tasks/1
```

### Errors

Every error is JSON, never a stack trace:

```json
{
  "timestamp": "2026-10-24T10:20:00.123",
  "status": 400,
  "error": "Bad Request",
  "message": "Validation failed",
  "details": { "title": "Title is required" }
}
```

| Status | When |
|---|---|
| 400 | Validation failed, malformed JSON, unknown `status`/`priority`, bad date, non-numeric id |
| 404 | Task id does not exist (GET, PUT or DELETE) |
| 500 | Unexpected server error (details are only written to the server log) |

## Data storage and reset

Tasks are stored in an H2 file database at `./data/tasktrack.mv.db`, relative to the folder you start the app from (usually the project root). The `data/` folder is git-ignored.

To reset your local data: stop the app, then delete the `data/` folder (macOS/Linux: `rm -rf data`; Windows: `rmdir /s /q data`). It is recreated on the next start. Only do this in your own clone, because it deletes all your tasks.

The H2 web console is **disabled** by default. For local debugging only, you can start with `mvn spring-boot:run -Dspring-boot.run.arguments=--spring.h2.console.enabled=true` and open `http://localhost:8080/h2-console` (JDBC URL `jdbc:h2:file:./data/tasktrack`, user `sa`, empty password). Never enable it on a public server.

## Tests

```bash
mvn test
```

Tests use a separate in-memory database, so they never touch your `data/` folder.

## Troubleshooting

- **Port 8080 already in use**: stop the other program, or run on another port: `mvn spring-boot:run -Dspring-boot.run.arguments=--server.port=8081`.
- **`release version 21 not supported` or `invalid target release`**: your Maven is using an older Java. Check `java -version` and `mvn -version`; set `JAVA_HOME` to a JDK 21 and reopen your terminal.
- **`mvn` is not recognized**: install Maven and add its `bin` folder to `PATH`.
- **Page shows "Cannot reach the TaskTrack server"**: the backend is not running or crashed. Check the terminal output. Open the app through `http://localhost:8080`, not by double-clicking `index.html`.
- **Database locked or corrupt after a crash**: stop all running copies, then reset the data folder as described above.
